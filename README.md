# Apollo — статическая вёрстка

Многостраничный сайт Apollo: HTML/CSS/JS по макетам Figma (десктоп 1440, мобилка 375). Результат — папка `dist/` с готовыми статическими страницами, которую получает интегратор 1С-Битрикс (интеграция — на его стороне). 

## Запуск

```bash
npm i            # Node 18+, версии — по package-lock.json
npm run dev      # сборка + http://127.0.0.1:3000 с live reload
npm run build    # чистая сборка в dist/ — это и передаётся
npm run preview  # сборка + просмотр dist без отслеживания
```

## Структура

```
src/
├── index.html             главная                         → dist/index.html
├── pages/**/<page>.html   остальные страницы (папки любые) → dist/pages/**/<page>.html (те же папки)
├── pages/<page>/<name>/   уникальные секции страницы
├── sections/<name>/       общие секции (на нескольких страницах)
├── ui/<name>/             общие компоненты (карточки, кнопки, табы…)
├── layout/                head / header / footer / scripts — общие для всех страниц
├── data/*.json            данные для @@loop
├── scss/                  токены (_variables), Bootstrap, база; template_styles.scss — точка входа
├── js/                    main.js — точка входа, core.js — общий код
├── vendor/                библиотеки (Bootstrap JS, Swiper) → vendor.js / vendor.css
├── icons/  img/  fonts/  root/
dist/                      готовая статика: index.html, pages/, css/, js/, img/, fonts/, favicon, manifest
```

## Принципы

- Один блок — одна реализация: HTML-партиал + `_<name>.scss` (+ `<name>.js`) в одной папке; контент — параметрами `@@include` и данными `@@loop`, различия — модификаторами `--<mod>`.
- Ссылки между страницами — абсолютные адреса сайта без слэша в конце (`/`, `/catalog`, `/blog/<slug>`); адрес повторяет папки страницы: `src/pages/brands/apollo.html` → `/brands/apollo` (так же работают dev/preview-сервер и GitHub Pages). Ресурсы (CSS, JS, картинки, шрифты) — через `@@root` (`@@root/css/…`, `@@root/img/…`): сборка подставит `.`, `..`, `../..` по месту страницы. Смотреть вёрстку — через `npm run dev` / `npm run preview`.
- В `dist/` — только раскрытый HTML: сборка падает, если осталась конструкция `@@…` или PHP-вставка.
- Общие стили компонентов — один раз в `template_styles.css`; секции их не дублируют.
- БЭМ с префиксом `ap-`; токены — только из `scss/_variables.scss`.
- Bootstrap 5.3: сетка, reboot, раскладочные утилиты; брейкпоинты стандартные.
- Размеры в px из макета → rem при сборке; вёрстка пропорционально масштабируется ниже 375px и от 1920px.
- Библиотеки — только в `vendor.js`, наш код — читаемый `script.js`.

## Интерактив: что переключается в вёрстке, а что — ссылки

Табы, которые меняют содержимое **на той же странице** (ARIA tablist, модуль `ui/tabs/tabs.js`):
- главная — категории товаров («Все», «Ножи», …);
- блог — рубрики «Новости и новинки», «Выбор и уход», … (`ui/line-tabs`), у каждой рубрики свои страницы и «Показать еще»;
- каталог — «Категории / Коллекции».

Табы-якоря (переход к разделу той же страницы, текущий подсвечивается при прокрутке): карточка товара —
«О товаре / Характеристики / Доставка и оплата / Отзывы»; оглавление статьи.

**Ссылки, а не табы** (каждый пункт — отдельная страница): навигация по категориям над заголовком категории
(`ui/line-tabs --nav`: «Ножи / Столовые приборы / …», текущая — `aria-current="page"`), крошки, меню, подвал.
Пока страниц нет, ссылки — заглушки `data-stub`.

Отзывы товара: блок выводится только с `reviews: true` (иначе — приглашение оставить отзыв); «Оставить отзыв» открывает форму,
если у секции `data-authorized="true"` (ставит сервер), иначе — окно «Войдите, чтобы оставить отзыв».

### Проверка вёрстки «как авторизованный пользователь» — `?auth`

В статике авторизации нет, поэтому на карточке товара по умолчанию «Оставить отзыв» открывает окно
«Войдите, чтобы оставить отзыв». Чтобы посмотреть форму отзыва, добавьте к адресу страницы `?auth`:

```
http://127.0.0.1:3000/catalog/nozhi/nozh-dlya-ovoshchey/nozh-dlya-ovoshchey-swift?auth
```

`sections/product-reviews/product-reviews.js` видит параметр и ведёт себя так, будто у секции стоит
`data-authorized="true"`: кнопки «Оставить отзыв» (в блоке оценки и в приглашении) открывают форму `#review-modal`.
Это только для просмотра вёрстки: на сайте признак ставит сервер (`data-authorized="true"` для вошедших), а проверку
`?auth` в скрипте интегратор может удалить.

`?auth` действует и в шапке: иконка «Личный кабинет» открывает меню «Мои заказы / Личные данные / Выйти»
(см. «Вход, регистрация и личный кабинет»).

Остальное поведение — в вёрстке, без сервера: вид списка «сетка / крупная сетка / список» (`ui/view-switch`),
«Показать ещё» (открывает уже выведенные скрытые карточки — на сайте заменяется подгрузкой), пагинация блога,
оглавление статьи, фильтры и сортировка (только интерфейс), формы с проверкой, модальные окна, меню каталога.

## Поиск

Поле поиска — общий компонент `ui/search`: в шапке (≥ 768) подсказки открываются под полем, на мобилке лупа
в нижней панели открывает лист с полем и подсказками над панелью. Подсказки — с 2 символов: категории (лупа,
название, стрелка), товары (фото, название, цена), «Показать все результаты →»; если ничего нет — «Ничего не найдено».
Enter и «Показать все результаты» ведут на страницу `/search?q=<запрос>`.

**Как посмотреть в статике.** Подсказки сейчас — пример из `data/search-categories.json` и `data/search-products.json`,
их фильтрует JS по тексту (атрибут `data-search-demo` у панели). Введите «нож» — подсказки, «лук» — «Ничего не найдено».
Страница результатов: `http://127.0.0.1:3000/search?q=нож` — найденные товары, `…/search?q=лук` — «Пока ничего не нашлось».

### Подсказки: подключение к серверу

У панели подсказок (`.ap-search-panel` в `ui/search/search-panel.html`; на странице их две — в шапке и в нижней
панели) убрать `data-search-demo` и выбрать один из способов.

**1. Адрес обработчика — `data-search-url` (рекомендуется, свой JS не нужен):**

```html
<div class="ap-search-panel ap-search-panel--drop" id="search-panel" hidden data-search-panel data-search-url="/ajax/search.php">
```

Скрипт сам отправляет `GET /ajax/search.php?q=<запрос>` (с заголовком `X-Requested-With: XMLHttpRequest`),
отменяет устаревшие запросы, пока пользователь печатает, и вставляет ответ в `[data-search-lists]`.
Ответ — HTML двух списков в разметке вёрстки (пустой список или пустой ответ — блок скрывается; ничего нет —
«Ничего не найдено»; ошибка сервера — панель закрывается):

```html
<ul class="ap-search-panel__list ap-search-panel__list--cats" data-search-list>
  <li data-search-item><a class="ap-search-panel__cat d-flex align-items-center justify-content-between gap-3" href="/catalog/nozhi"><span class="d-flex align-items-center gap-2"><svg class="ap-icon" aria-hidden="true"><use href="/img/sprite.svg#search"></use></svg>Ножи</span><svg class="ap-icon ap-search-panel__arrow" aria-hidden="true"><use href="/img/sprite.svg#arrow-long"></use></svg></a></li>
</ul>
<ul class="ap-search-panel__list ap-search-panel__list--products" data-search-list>
  <li data-search-item><a class="ap-search-panel__product d-flex align-items-center gap-2" href="/catalog/…"><img class="ap-search-panel__img" src="/upload/…" width="96" height="96" alt="" loading="lazy"><span class="ap-search-panel__name">Нож поварской Genio Loft, 20&nbsp;см</span><span class="ap-search-panel__price">1&nbsp;490&nbsp;₽</span></a></li>
</ul>
```

Разметка пунктов — те же партиалы `ui/search/search-category.html` и `ui/search/search-product.html`
(в Битриксе — например, шаблон компонента `bitrix:search.title` или свой AJAX-обработчик по каталогу).

**2. Свой JS — события.** Без `data-search-url` скрипт только отправляет `ap:search-query` и ждёт, пока интегратор
выведет пункты в списки `[data-search-list]` и сообщит панели `ap:search-update` — до этого панель не открывается:

```js
document.addEventListener('ap:search-query', async ({ detail: { query, panel } }) => {
  const html = await (await fetch(`/ajax/search.php?q=${encodeURIComponent(query)}`)).text();
  panel.querySelector('[data-search-lists]').innerHTML = html;
  panel.dispatchEvent(new CustomEvent('ap:search-update'));
});
```

### Страница результатов `/search?q=<запрос>`

Собирает сервер, без AJAX. В `pages/search.html` — оба варианта, лишний скрыт атрибутом `hidden`:

- `[data-search-results]` — найдено: крошки + блок каталога `sections/category` (без навигации и описания)
  с найденными товарами; заголовок «Результаты по запросу «…»» (`[data-search-query]`). Сортировка, вид, фильтр,
  «Показать ещё» — как на странице категории (те же события);
- `[data-search-nothing]` — ничего не найдено: крошки по центру + `sections/empty-state`.

Сервер выводит только нужный блок (без `hidden`), атрибут `data-search-demo` у `<main>` убирается — тогда скрипт
только подставляет запрос из адреса в заголовок и в поле поиска.

## Корзина

Страница `pages/cart.html`, секция `pages/cart/cart-content` (товары — `cart-item.html`, данные — `data/cart-items.json`).

- Товар: цена за штуку — `data-price`, количество — `ui/quantity` (`max` — остаток). Сумма строки, «Товары, N шт.», сумма
  и «Итого» (сумма − скидка из `data-cart-discount` у сводки) пересчитываются в вёрстке; счётчик корзины в шапке —
  событием `ap:counter`. Сервер выводит те же числа сразу.
- Нет в наличии — `unavailable: true` в данных (`data-cart-unavailable`): «Сообщить о поступлении», «Похожие товары →».
  Пояснение к товару («Доступно 2 шт. вместо 3…») — поле `note`.
- Вид страницы выбирается сам по товарам: есть в наличии — список, промокод, сводка; только недоступные —
  «Товары в корзине пока недоступны»; ничего — «В корзине пока пусто». Меняется и при удалении товаров.
- «Уже покупали у нас?» и «Можно оформить без регистрации» — только гостю (скрыты, если `data-authorized="true"` у `[data-account]`).
- Промокод: форма `[data-cart-promo]` → `ap:form-submit`; ответ сервера — событие `ap:promo-result`:

  ```js
  document.dispatchEvent(new CustomEvent('ap:promo-result', {
    detail: { form, ok: true, message: 'Промокод на скидку 20 % применен', discount: 1000 },
  }));
  ```

  Применён — поле только для чтения с кнопкой «очистить» (очистка — `ap:promo-remove`), ошибка (`ok: false`) —
  красное поле и текст. `message` необязателен (по умолчанию — `data-promo-success` / `data-promo-error` формы),
  `discount` — новая скидка в рублях, итог пересчитается.

**Демо-корзина (только статичная вёрстка).** Пока у `<body>` есть атрибут `data-demo` (`layout/head.html`),
корзина работает в браузере без сервера (`js/cart-demo.js`, `localStorage`): «В корзину» в карточке товара и на странице
товара (с выбранным количеством) добавляет товар, счётчик корзины в шапке и нижней панели показывает число товаров
на любой странице, `/cart` выводит добавленное (по шаблонам `<template data-cart-template…>` — та же разметка
`cart-item.html`) и запоминает изменения количества и удаление. При первом открытии `/cart` начальной корзиной
становится пример из `data/cart-items.json`; `?cart-reset` в адресе любой страницы очищает демо-корзину.
**На сайте атрибут `data-demo` убрать** — тогда модуль ничего не делает, товары и счётчик выводит сервер,
а шаблоны в корзине можно удалить.

**Как посмотреть:** `http://127.0.0.1:3000/cart`, `…/cart?unavailable`, `…/cart?empty`, `…/cart?auth` (без блока входа),
`…/cart?promo-error` (промокод не принимается; без параметра любой код «применяется»).

## Избранное и сравнение

**Избранное** (`pages/favorites.html`, секция `pages/favorites/favorites-list`, данные — `data/favorites-products.json`):
карточки `ui/product-card` с параметром `favorite: true` (сердце закрашено и видно на всех ширинах); товар не в наличии —
`unavailable: true` + `similar` (ссылка «Похожие товары →» и метка «Нет в наличии» вместо цены). Снятое сердце приглушает
карточку до перезагрузки (запрос на сервер — по `ap:product-action`). Сортировка переставляет карточки в вёрстке
(«недавно добавленные» — порядок вывода сервера). Плашка «Сохраните избранное в профиле» — только гостю.

**Сравнение** (`pages/compare.html`, секция `pages/compare/compare-table`): у каждой категории свой таб и таблица.
Данные категории — два файла: `data/compare-<категория>-products.json` (товары: `col` — номер колонки, `slot` — `a` / `b` —
какие два товара видны на мобилке, `pos` / `total` — «1 из 3») и `data/compare-<категория>-specs.json` (характеристики:
`name`, `values` — значения по колонкам). Крестик убирает товар (`ap:compare-remove`), «Очистить сравнение» —
`ap:compare-clear`; «Показать только различия» скрывает строки с одинаковыми значениями. На мобилке видны два товара,
«< 1 из 3 >» листает товары в колонке.

Демо-режим (тот же атрибут `data-demo`, `js/favorites-demo.js`): избранное хранится в `localStorage`. Сердце на любой
странице — в карточке товара (каталог, главная, поиск), на странице товара, в сравнении, в корзине — добавляет товар
(сверху — недавно добавленные) или убирает его; после обновления страницы сердца отмеченных товаров закрашены, счётчик
в шапке — по их числу. `/favorites` выводит сохранённые товары по шаблонам `<template data-favorites-template…>`
(та же `ui/product-card`); снятый товар после обновления пропадает, не осталось ни одного — «В избранном пока пусто».
При первом открытии `/favorites` начальным избранным становится пример из `data/favorites-products.json`;
`?favorites-reset` в адресе — очистить. На сайте атрибут убирается — товары и сердца выводит сервер, шаблоны не нужны.

**Как посмотреть:** `/favorites`, `/favorites?empty`, `/favorites?auth` (без плашки входа), `/compare`, `/compare?empty`.

## Технические работы

Страница `pages/maintenance.html` (`sections/empty-state`, вид `page`): «Сайт временно недоступен», «Обновить страницу →»,
«Спасибо за терпение!».

**Как посмотреть:** `npm run dev` → `http://127.0.0.1:3000/maintenance` (или `npm run preview`;
в `dist/` — файл `pages/maintenance.html`).

**Как подключить на сайте.** На время работ сервер отдаёт эту страницу **на том адресе, который запросил
пользователь** (код ответа `503 Service Unavailable`, желательно с заголовком `Retry-After`; адрес в браузере не меняется).
Тогда «Обновить страницу» просто перезагружает этот адрес — пользователь вернётся туда, где был.
У кнопки `href=""` — это текущий адрес, поэтому она работает даже без JS.

Если вместо этого сервер **перенаправляет** на отдельный адрес, исходный путь нужно передать в `?back=`:
`/maintenance?back=/catalog/nozhi` — кнопка поведёт на `/catalog/nozhi`. Принимаются только пути этого же сайта
(начинаются с `/`), внешние ссылки игнорируются (`sections/empty-state/empty-state.js`).

## Вход, регистрация и личный кабинет

Окна — `layout/modal-auth.html` и `layout/modal-auth-code.html` (подключены после подвала, есть на всех страницах),
логика — `layout/auth.js`.

- Иконка «Личный кабинет» (шапка, нижняя панель) у гостя открывает «Вход или регистрация»: табы «По телефону /
  По почте», «Получить код» → окно «Введите код». Код отправляется сам, когда введены 4 цифры.
- «Войти по почте / по телефону» — окно входа с паролем (вид меняется: заголовок, поле, текст ошибки).
- Почта: если она уже зарегистрирована — окно входа с паролем, иначе — регистрация через код. Решает сервер:
  `document.dispatchEvent(new CustomEvent('ap:auth-email', { detail: { form, registered: true } }))`.
- Неверный код / пароль — `ap:auth-error` (`detail: { form }`): «Неверный код» в окне кода, красные поля и текст
  ошибки в окне входа.
- Вошедший пользователь (`data-authorized="true"` у `[data-account]` в шапке и нижней панели — ставит сервер):
  иконка открывает меню «Мои заказы / Личные данные / Выйти»; «Выйти» → окно «Выйти из профиля?».

**Как посмотреть в статике** (ответ сервера имитируется, пока у форм `action="#"`):

| Адрес | Что видно |
|---|---|
| любая страница | гость: иконка кабинета → «Вход или регистрация»; любой код из 4 цифр → «Спасибо за регистрацию!» |
| `?auth-registered` | «Получить код» по почте → окно входа с паролем (почта зарегистрирована) |
| `?auth-error` | любой код → «Неверный код», вход по паролю → ошибка |
| `?auth` | вошедший пользователь: меню кабинета; «Выйти» в окне перезагружает страницу без `?auth` |
