# Apollo — статическая вёрстка

Многостраничный сайт Apollo: HTML/CSS/JS по макетам Figma (десктоп 1440, мобилка 375). Результат — папка `dist/` с готовыми статическими страницами, которую получает интегратор 1С-Битрикс (интеграция — на его стороне). Правила разработки — в [CLAUDE.md](CLAUDE.md).

## Запуск

```bash
npm i            # Node 18+, версии — по package-lock.json
npm run dev      # сборка + http://127.0.0.1:3000 с live reload
npm run build    # чистая сборка в dist/ — это и передаётся
npm run preview  # сборка + просмотр dist без отслеживания
```

## Структура

```
src/
├── index.html             главная                         → dist/index.html
├── pages/<page>.html      остальные страницы              → dist/pages/<page>.html
├── pages/<page>/<name>/   уникальные секции страницы
├── sections/<name>/       общие секции (на нескольких страницах)
├── ui/<name>/             общие компоненты (карточки, кнопки, табы…)
├── layout/                head / header / footer / scripts — общие для всех страниц
├── data/*.json            данные для @@loop
├── scss/                  токены (_variables), Bootstrap, база; template_styles.scss — точка входа
├── js/                    main.js — точка входа, core.js — общий код
├── vendor/                библиотеки (Bootstrap JS, Swiper) → vendor.js / vendor.css
├── icons/  img/  fonts/  root/
dist/                      готовая статика: index.html, pages/, css/, js/, img/, fonts/, favicon, manifest
```

## Принципы

- Один блок — одна реализация: HTML-партиал + `_<name>.scss` (+ `<name>.js`) в одной папке; контент — параметрами `@@include` и данными `@@loop`, различия — модификаторами `--<mod>`.
- Ссылки между страницами — абсолютные адреса сайта без слэша в конце (`/`, `/catalog`, `/blog/<slug>`); dev/preview-сервер сопоставляет их файлам `pages/*.html`. Ресурсы (CSS, JS, картинки, шрифты) — через `@@root` (`@@root/css/…`, `@@root/img/…`): сборка подставит `.` или `..` по месту страницы. Смотреть вёрстку — через `npm run dev` / `npm run preview`.
- В `dist/` — только раскрытый HTML: сборка падает, если осталась конструкция `@@…` или PHP-вставка.
- Общие стили компонентов — один раз в `template_styles.css`; секции их не дублируют.
- БЭМ с префиксом `ap-`; токены — только из `scss/_variables.scss`.
- Bootstrap 5.3: сетка, reboot, раскладочные утилиты; брейкпоинты стандартные.
- Размеры в px из макета → rem при сборке; вёрстка пропорционально масштабируется ниже 375px и от 1920px.
- Библиотеки — только в `vendor.js`, наш код — читаемый `script.js`.

## Интерактив: что переключается в вёрстке, а что — ссылки

Табы, которые меняют содержимое **на той же странице** (ARIA tablist, модуль `ui/tabs/tabs.js`):
- главная — категории товаров («Все», «Ножи», …);
- блог — рубрики «Новости и новинки», «Выбор и уход», … (`ui/line-tabs`), у каждой рубрики свои страницы и «Показать еще»;
- каталог — «Категории / Коллекции».

Табы-якоря (переход к разделу той же страницы, текущий подсвечивается при прокрутке): карточка товара —
«О товаре / Характеристики / Доставка и оплата / Отзывы»; оглавление статьи.

**Ссылки, а не табы** (каждый пункт — отдельная страница): навигация по категориям над заголовком категории
(`ui/line-tabs --nav`: «Ножи / Столовые приборы / …», текущая — `aria-current="page"`), крошки, меню, подвал.
Пока страниц нет, ссылки — заглушки `data-stub`.

Отзывы товара: блок выводится только с `reviews: true` (иначе — приглашение оставить отзыв); «Оставить отзыв» открывает форму,
если у секции `data-authorized="true"` (ставит сервер), иначе — окно «Войдите, чтобы оставить отзыв».

### Проверка вёрстки «как авторизованный пользователь» — `?auth`

В статике авторизации нет, поэтому на карточке товара по умолчанию «Оставить отзыв» открывает окно
«Войдите, чтобы оставить отзыв». Чтобы посмотреть форму отзыва, добавьте к адресу страницы `?auth`:

```
http://127.0.0.1:3000/catalog/nozhi/nozh-dlya-ovoshchey-swift?auth
```

`sections/product-reviews/product-reviews.js` видит параметр и ведёт себя так, будто у секции стоит
`data-authorized="true"`: кнопки «Оставить отзыв» (в блоке оценки и в приглашении) открывают форму `#review-modal`.
Это только для просмотра вёрстки: на сайте признак ставит сервер (`data-authorized="true"` для вошедших), а проверку
`?auth` в скрипте интегратор может удалить.
Поиск в шапке: крестик «Очистить» появляется, когда в поле есть текст.

Остальное поведение — в вёрстке, без сервера: вид списка «сетка / крупная сетка / список» (`ui/view-switch`),
«Показать ещё» (открывает уже выведенные скрытые карточки — на сайте заменяется подгрузкой), пагинация блога,
оглавление статьи, фильтры и сортировка (только интерфейс), формы с проверкой, модальные окна, меню каталога.

### События для подключения к серверу

| Событие | Где | `detail` |
|---|---|---|
| `ap:counter`, `ap:counter-change` | шапка, нижняя панель — счётчики сравнения / избранного / корзины | `{ counter, count }` / `{ counter, delta }` |
| `ap:product-action` | карточка товара — сравнение, избранное, корзина | `{ action, active, card }` |
| `ap:products-more` | «Показать ещё» — товары, коллекции, категория | `{ root, brand, shown, total }` |
| `ap:articles-page` | блог — страница / «Показать еще» | `{ panel, from, to, last }` |
| `ap:filters-change` | фильтры категории (`ui/filters`) | `{ form, data: FormData, active }` |
| `ap:sort-change` | сортировка категории и отзывов товара | `{ value }` |
| `ap:quantity-change` | выбор количества на карточке товара | `{ value }` |
| `ap:view-change` | вид списка (`ui/view-switch`) | `{ view, targets }` |
| `ap:form-submit` | формы (подписка, «Подобрать для проекта», «Написать нам») после проверки | `{ form, data: FormData }` |
